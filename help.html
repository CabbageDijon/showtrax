Zero‑Idle Local Storage Strategy

All user data resides exclusively in the browser’s localStorage. There is no backend server and no persistent database process. This means:

  • Zero RAM overhead – No server‑side session or database daemon runs on the VPS.
  • User credentials, watchlists and preferences are stored per browser and never transmitted to the server.
  • The system simulates a lightweight SQLite‑like store purely client‑side using JSON serialisation.
  • Guest users receive a random UUID to isolate their watchlist.

The “Export Cloud Backup” button creates a downloadable .json file that can be manually uploaded to a Cloudflare R2 / S3 bucket, effectively offloading state from the tiny 18GB NVMe disk.

DevOps Decisions

  • Nginx Alpine – Tiny footprint (~5 MB base), perfect for 2GB RAM limit.
  • Vanilla JS + Tailwind CDN – Zero build step, no node_modules, immediate delivery.
  • Gzip static compression – Enabled in nginx.conf to minimise bandwidth.
  • Immutable static assets – All files are served directly; no runtime writes.
  • Coolify deployment – Single Dockerfile, pull & run, automatic health checks.

Coolify Deployment Steps (Quick Reference)

  1. Push the entire project folder to a Git repository.
  2. In Coolify, create a new service → Dockerfile.
  3. Point to your repository and the branch containing the Dockerfile.
  4. Set the port to 80 (or map a custom domain).
  5. Deploy – Coolify will build the image and start the container.
